# Database Schema Design Guide

MUDDA는 **Flyway**를 마이그레이션 도구로 확정 사용한다(Liquibase 미사용). 마이그레이션 파일 경로는 `src/main/resources/db/migration/`.

## Naming Conventions

- Tables: `snake_case`, plural (`users`, `api_keys`)
- Columns: `snake_case` (`created_at`, `is_active`)
- FK columns: `{referenced_table_singular}_id` (`user_id`, `club_id`)
- Index names: `idx_{table}_{columns}` (`idx_users_email`)
- UK names: `uq_{table}_{columns}` (`uq_users_email`)

## Standard Columns

Include in every entity table:

```sql
id         BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
created_at DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
updated_at DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6)
```

## Index Strategy

- Single column used frequently in WHERE: simple index
- WHERE + ORDER BY combination: composite index (WHERE column first)
- Low-cardinality columns (`is_active`, `status` enum): indexing rarely helps

```sql
-- Composite index example
CREATE INDEX idx_posts_user_created ON posts (user_id, created_at DESC);
```

## PostGIS Geometry Columns

MUDDA는 `hibernate-spatial` + `jts-core`로 공간 데이터를 다룬다.

- Geometry 컬럼은 SRID **4326**(WGS84, 위경도)을 기본으로 사용한다.
- 공간 인덱스는 `USING GIST`로 생성한다:
  ```sql
  ALTER TABLE places ADD COLUMN location GEOMETRY(Point, 4326);
  CREATE INDEX idx_places_location ON places USING GIST (location);
  ```
- PostGIS 확장은 **권한 문제 때문에 Flyway 마이그레이션 안에서 직접 `CREATE EXTENSION`을 실행하면 실패할 수 있다**(관리자 권한 필요). MUDDA는 이를 피하려고 `src/main/resources/db/init/001_enable_postgis.sql`을 docker-compose의 `docker-entrypoint-initdb.d`로 마운트해 컨테이너 최초 기동 시 미리 확장을 활성화해두고, Flyway 마이그레이션(`V1__init_postgis.sql`)은 그 이후 스키마 변경만 담당한다. 새 PostGIS 관련 변경도 이 분리 방식을 유지한다.
- JTS(`org.locationtech.jts`) `Geometry`/`Point` 타입을 엔티티 필드로 매핑할 때는 `@Column(columnDefinition = "geometry(Point,4326)")`를 명시한다.

## Migration — Flyway

파일 네이밍: `V{version}__{description}.sql`, 경로: `src/main/resources/db/migration/`

```
src/main/resources/db/migration/
  V1__init_postgis.sql
  V2__add_api_keys.sql
```

```sql
-- V2__add_api_keys.sql
CREATE TABLE api_keys (
    id         BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id    BIGINT      NOT NULL,
    key_value  VARCHAR(64) NOT NULL,
    created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    CONSTRAINT fk_api_keys_user FOREIGN KEY (user_id) REFERENCES users (id),
    CONSTRAINT uq_api_keys_value UNIQUE (key_value)
);
```

## JPA Entity Mapping

```kotlin
@Entity
@Table(name = "api_keys")
class ApiKey(
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", nullable = false)
    val user: User,

    @Column(name = "key_value", nullable = false, unique = true, length = 64)
    val keyValue: String,
) : BaseEntity()
```
